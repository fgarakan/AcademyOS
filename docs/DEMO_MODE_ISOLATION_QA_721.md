## Demo Mode Detection

All demo mode detection flows through one of two patterns:

**Pattern A — `isDemoMode()` utility:**
```ts
// src/lib/donna/cooDemo.ts
export function isDemoMode(searchParams): boolean {
  const val = searchParams['demo']
  return val === '1' || val === 'true'
}
```

**Pattern B — Inline check:**
```ts
const isDemoMode = searchParams.demo === '1'
```

Both patterns are URL-param gated. Demo data is never injected unless `?demo=1` is present in the URL.

## Demo Data ID Patterns

All demo data uses clearly prefixed IDs:
- `demo-session-1`, `demo-session-2`
- `demo-coach-1`
- `demo-template-1`, `demo-group-1`
- `demo-player-1`
- `demo-review-001`

These IDs cannot collide with real DB records because:
1. Real DB records use `uuid()` format (e.g., `3f2a4b1c-...`)
2. Demo data is injected at the page layer before component rendering
3. Demo data never reaches the Supabase query layer — it bypasses DB entirely
