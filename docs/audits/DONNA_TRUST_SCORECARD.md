# DONNA Trust Scorecard V2

**Updated: Mega Sprint 2021–2050 — June 2026**
**Previous version: Sprint 2020A**

> Trust is the only metric that matters for an operating partner.
> A director who doesn't trust DONNA will not use DONNA.
> A director who uses an untrusted DONNA will eventually get burned.

---

## Scoring Methodology

Each DONNA output type is scored on five dimensions:

| Dimension | What it measures |
|---|---|
| **Confidence** | Does DONNA accurately signal how certain it is? |
| **Evidence** | Is there real data behind this output? |
| **Explainability** | Can the director understand why DONNA said this? |
| **Actionability** | Can the director do something specific with this? |
| **Trustworthiness** | Would a skeptical director believe this? |

Each dimension: 0–20 points. Total: 0–100.

**Ratings:**
- 85–100: Production-ready. Director can rely on this without second-guessing.
- 70–84: Mostly reliable. Acceptable with known caveats.
- 55–69: Useful but unreliable. Treat as suggestions, not recommendations.
- 40–54: Unreliable. High risk of misdirecting the director.
- 0–39: Do not surface. Actively harmful to trust.

## 3. Action Drafts

### What is being scored:
The `DonnaActionDraft[]` generated by `donnaDraftBuilder` and surfaced via `DonnaDraftCard` on domain pages.

| Dimension | Score | Reasoning |
|---|---|---|
| Confidence | 12/20 | Drafts inherit source engine confidence but don't display it. The director sees a card with no confidence indicator. |
| Evidence | 10/20 | Drafts are built from decision outputs, which are partially data-starved. A "Schedule reassessment for 3 players" draft is correct when those 3 players are truly overdue — but the source data is a player status filter that may not perfectly capture "overdue." |
| Explainability | 13/20 | `description` field explains the signal. `sourceEngine` is available but not displayed. Director sees the label and description only. |
| Actionability | 16/20 | `actionTarget.route` navigates correctly for most actions. The "Review"/"Open" button directly takes the director where they need to go. High actionability for navigation-type actions. |
| Trustworthiness | 10/20 | Entity-less drafts (e.g., "Create coach note" navigating to player directory) actively damage trust. A director who follows one of these and finds nothing useful will dismiss future drafts without reading them. |

**Total: 61/100**
**Rating: Useful but unreliable. Navigation-only actions (open_approval, review_advancement, review_curriculum_recommendation) are trustworthy. Entity-bound actions (create_coach_note, create_player_note) are not.**

## COO Reality Assessment

**Scenario:** You are the COO of a 500-player academy. You use DONNA daily.

**Would DONNA help you?**
Yes — for curriculum decisions (high value), approval queue management (reliable), and advancement reviews (reliable).

**Would DONNA annoy you?**
Yes — when it shows the same 3 priorities for 3 sessions in a row without them being resolved. When "what changed" shows things that didn't change. When an action draft navigates to the wrong place.

**Would DONNA save time?**
Yes — if you use the navigation-type actions. "Open Approval Queue" and "Review Advancement" genuinely reduce clicks. Curriculum recommendations are the most time-saving feature when they fire.

**Would DONNA create work?**
Sometimes — when priorities are based on incomplete data and send you to investigate something that turns out not to be a real problem. This currently happens with coach execution priorities (since coach execution data is hardcoded to 0, the signal that fires is based on session recap counts only — which may be a different problem).

**Would DONNA be trusted?**
By a patient director who understands it is V1: yes. By a director expecting production-grade recommendations: no. Expectation calibration is currently the most important trust intervention.

**Would DONNA be used daily?**
Yes for the Today page quick orientation. The 3-decision layout reduces cognitive load. Even with imperfect decisions, having a structured starting point is valuable.

**Overall COO Assessment: Promising V1. Curriculum system is production-ready. Director decisions need data pipeline improvements before they earn unconditional trust.**

## Trust Improvement Priority Order

1. **Fix parent signal conflation** — one signal from one data point (quick, high trust impact)
2. **Remove entity-less action drafts** — stop generating drafts that navigate to wrong place (quick, high trust impact)
3. **Fix fallback priorities** — do not surface "gather data" priorities for data that exists but is not loaded (medium effort, high trust impact)
4. **Load actual data for top 3 empty fields** — `readinessBlockerCount`, `inconsistentExecutionCount`, `weakLevelCount` (medium effort, very high trust impact)
5. **Real delta for What Changed** — store a snapshot on each visit and compute actual changes (high effort, high trust impact)
6. **Domain-specific decision prompts** — replace generic prompts with content-derived binary choices (medium effort, medium trust impact)
