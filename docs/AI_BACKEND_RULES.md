# AI Backend Rules

These rules apply to every Claude Code session.
Backend files must not be modified without an explicit instruction to do so.
Read this file before touching any file in `src/lib/`.

---

## 1. NEVER use `.single<Type>()`

`.single<Type>()` is not a valid Supabase JS v2 call and will cause a TypeScript error.

Use `.single()` without a generic, then cast or destructure the result.

```ts
// WRONG
const { data } = await db.from('players').select('*').eq('id', id).single<Player>()

// CORRECT
const { data } = await db.from('players').select('*').eq('id', id).single()
```

---

## 2. NEVER invent `Enums<'...'>` values

Only use `Enums<'enum_name'>` if that exact enum name exists in `src/lib/supabase/database.types.ts`.

Before using any enum, grep for it:

```bash
grep -n '"enum_name"' src/lib/supabase/database.types.ts
```

If it does not appear in `Enums`, do not use it.

---

## 3. If unsure about an enum, use a plain string union

When the enum name is unclear or the type is complex, fall back to a string union or `string`.

```ts
// Acceptable fallback
type AssessmentType = 'intake' | 'quarterly' | 'reassessment' | 'ad_hoc'

// Or just
status: string
```

Do not guess enum names.

---

## 4. If TS2589 ("type instantiation excessively deep") appears, use `rawDb`

TS2589 is a Supabase inference recursion limit, not a logic error. Fix it locally:

```ts
const rawDb = db as any
const { data, error } = await rawDb.from('table').select('*, relation(*)')
```

Apply this cast only to the specific query that triggers the error.
Do not cast the entire backend file. Do not remove the typed `DB` type from the function signature.

---

## 5. Prefer sequential Supabase queries over `Promise.all` for relational data

Supabase RLS policies can behave unexpectedly under parallel execution.
Run related queries sequentially unless there is a confirmed performance reason to parallelize.

```ts
// Preferred
const { data: player } = await db.from('players').select('*').eq('id', id).single()
const { data: signals } = await db.from('player_development_signals').select('*').eq('player_id', id)

// Avoid unless justified
const [playerRes, signalsRes] = await Promise.all([...])
```

---

## 6. Do not introduce recursive helper types such as `PlayerWithRelations`

Recursive or deeply nested TypeScript helper types cause TS2589 and make type inference unpredictable with Supabase.

Use the generated types from `database.types.ts` directly:

```ts
type Player = Tables<'players'>
type Signal = Tables<'player_development_signals'>
```

If you need a combined shape, define it as a flat intersection only when needed at the component boundary, not in the backend file.

---

## 7. Do not refactor working backend files just to improve typing

If a backend file compiles cleanly and the runtime works, leave it alone.
Typing improvements are not a valid reason to modify a backend file.
Backend stability is more important than type elegance.

---

## 8. Priority order: compile → runtime → types

When a conflict exists between perfect types and a working build:

1. Code must compile (`npx tsc --noEmit` passes)
2. Runtime must work (queries return data, mutations succeed)
3. Types are a nice-to-have — use `as any` sparingly when needed

Never sacrifice a working runtime to achieve cleaner types.

---

## 9. Do not touch backend files unless the task explicitly requires it

The files in `src/lib/backend/` are stable and compile cleanly.
Do not open, edit, or refactor them unless the current task description explicitly names the file.

If you believe a backend file needs a change, state that clearly before touching it and explain why.

---

## 10. Always run `npx tsc --noEmit` after any backend-related change

After any edit to `src/lib/`, `src/app/api/`, or `src/middleware.ts`, run:

```bash
npx tsc --noEmit
```

Do not report a task as complete if TypeScript errors exist.
If a new error appears in a file you did not touch, note it but do not fix it unless instructed.

---

## Source of truth for types

All database types come from:

```
src/lib/supabase/database.types.ts
```

This file is generated by `supabase gen types typescript`. Do not edit it by hand.
If a table or column appears to be missing from the types, run type generation again — do not add it manually.
